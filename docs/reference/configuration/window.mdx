# Window
This type specifies a single window that is used to render content into. There can be an arbitrary(-ish) number of windows for each node and they all will be created and initialized at start time. Each window has at least one [Viewport](viewport) that specifies exactly where in the window the rendering occurs with which parameters.

## Parameters
<Parameter name="pos" type={<Link to="/docs/reference/configuration/basetypes#ivec2">ivec2</Link>} optional default="0,0">
Sets the position of the window on the overall desktop space provided by the operating system. This object must have the integer values `x` and `y` that specify the x-y location of the window. Please note that these values also can be negative on some operating systems. On Windows, for example, the top left corner of the primary monitor is `(0,0)` in this coordinate system, but there can be additional monitors to the left or the top of the primary monitor, which would require negative numbers.
</Parameter>

<Parameter name="size" type={<Link to="/docs/reference/configuration/basetypes#ivec2">ivec2</Link>}>
Sets the size of the window in pixels. This object must have the integer values `x` and `y` that determine the size of the window.
</Parameter>

<Parameter name="res" type={<Link to="/docs/reference/configuration/basetypes#ivec2">ivec2</Link>} optional>
Sets the size of the internal framebuffer that is used to render the contents of the window. In a lot of cases, this resolution is the same resolution as the size of the window, but it is a useful tool when creating images that are larger than a window would be supported on an operating system. Some operating systems restrict windows to be no larger than what can fit on a specific monitor. This object must have the integer values `x` and `y` that determine the size of the framebuffer. By default, the framebuffer has the same size as the window.
</Parameter>

<Parameter name="viewports" type={<><Link to="/docs/reference/configuration/viewport">Viewport</Link>[]</>} optional />

<Parameter name="id" type="integer" optional>
The numerical identifier of this window, which has to be between `0` and `127`. By default windows are given numerical value equal to their position in the node's `windows` list, meaning that the first window of a node will have the id `0`, the second window the id `1`, etc. This value can be used to overwrite this behavior. It is not allowed to give the same id to two different windows.
</Parameter>

<Parameter name="name" type="string" optional>
The name of the window. This is also used as the title of the window if window decorations are enabled. The default name for a window if this value is not specified is "SGCT node: `address` (`role`: `id`)" with `address` the address of this node, `role` either "server" or "client", depending on whether the current node is the server or a client in the cluster, and `id` the id of the window.
</Parameter>

<Parameter name="tags" type="string[]" optional>
A list of tags that are associated with this window. The tags themselves don't have any meaning inside of SGCT, but can be used by the application code as a filter. One common use-case is to tag one of the windows as a "GUI" window, to restrict input to only that window, for example.
</Parameter>

<Parameter name="bufferbitdepth" type="8, 16, 16f, 32f, 16i, 32i, 16ui, or 32ui" optional default="8">
Sets the bit depth and format of the color texture that is used as the render backend for this entire window. The values are converted to the following OpenGL parameters (internal color format and data type) for the texture creation:

  - `8`: `GL_RGBA8`, `GL_UNSIGNED_BYTE`
  - `16`: `GL_RGBA16`, `GL_UNSIGNED_SHORT`
  - `16f`: `GL_RGBA16F`, `GL_HALF_FLOAT`
  - `32f`: `GL_RGBA32F`, `GL_FLOAT`
  - `16i`: `GL_RGBA16I`, `GL_SHORT`
  - `32i`: `GL_RGBA32I`, `GL_INT`
  - `16ui`: `GL_RGBA16UI`, `GL_UNSIGNED_SHORT`
  - `32ui`: `GL_RGBA32UI`, `GL_UNSIGNED_INT`

</Parameter>

<Parameter name="fullscreen" type="boolean" optional default="false">
Determines whether the window should be created in an exclusive fullscreen mode. The `size` of this window will be used to set the screen resolution if this value is `true`. See also the `monitor` value to determine which monitor should be used as the target for the fullscreen window.
</Parameter>

<Parameter name="autoiconify" type="boolean" optional default="false">
Determines whether an exclusive fullscreen window will be automatically iconified if it loses focus. This value will be ignored if the `fullscreen` value is not set or if it is `false`.
</Parameter>

<Parameter name="hidemousecursor" type="boolean" optional default="false">
If this value is set to `true`, the mouse cursor will never be visible above this window.
</Parameter>

<Parameter name="floating" type="boolean" optional default="false">
Indicates whether the window is floating, meaning that it is rendered by the operating system always on top of other windows.
</Parameter>

<Parameter name="alwaysrender" type="boolean" optional default="false">
Determines whether the content of the window should continue to render even if the window is not visible on screen. Normally, the operating system will not invalidate a window when it is hidden (see `hidden` value) and this value can be used to overwrite that behavior.
</Parameter>

<Parameter name="hidden" type="boolean" optional default="false">
Determines whether this window should be visible on screen or used as an offscreen rendering target. If a window is hidden, you should also set `alwaysrender` to `true`, or otherwise the rendering might not occur as expected.
</Parameter>

<Parameter name="takescreenshot" type="boolean" optional default="true">
If this value is `false`, this window will not participate in taking screenshots even if commanded so by the user. This can be useful to prevent auxiliary windows to create screenshots in a production environment.
</Parameter>

<Parameter name="alpha" type="boolean" optional default="false">
Determines whether screenshots created from this window should include an alpha channel or not. If this value is false, the resulting image type is RGB, otherwise RGBA.
</Parameter>

<Parameter name="msaa" type="integer" optional default="1">
Determines whether multisample antialiasing is used for the window and how many subsamples should be used for the antialiasing. If the value is set to `0` or `1`, MSAA is disabled. MSAA operates by rendering the scene at a higher resolution using multiple samples per pixel and combining these samples to reduce aliasing. It produces good-looking results, but it increases the rendering time for the scene. The maximum number of samples depends on the GPU that is used to start the application, but is usually around 32. This value should not be used at the same time as `fxaa`.
</Parameter>

<Parameter name="fxaa" type="boolean" optional default="false">
Determines whether fast approximate antialiasing is used for the contents of this window. This antialiasing is a postprocessing that does not significantly increase rendering time, but the results are not as good as `msaa`. This value should not be used at the same time as `msaa`.
</Parameter>

<Parameter name="border" type="boolean" optional default="true">
Enables or disables window decorations. Window decorations are the title bar that contains the name of the window and buttons to close, maximize or minimize a window. On some operating systems, the window decorations also include a border around a window and potentially shadow effects and the ability to resize the window by dragging the border, all of which can be disabled with this value.
</Parameter>

<Parameter name="resizable" type="boolean" optional default="true">
Enables or disables the ability of the user to change the size of the window.
</Parameter>

<Parameter name="draw2d" type="boolean" optional default="true">
Determines whether the `draw2D` callback should be called for viewports in this window. In many applications this corresponds to user interface elements that are traditionally rendered in this step.
</Parameter>

<Parameter name="draw3d" type="boolean" optional default="true">
Determines whether the `draw` callback should be called for viewports in this window. In many applications, this is the rendering step that creates the 3D scene and renders it to the screen.
</Parameter>

<Parameter name="noerror" type="boolean" optional default="false">
If this value is set to `true` the graphics API will not perform any error checking. This means that any application will run slightly faster but will behave in an undefined manner in case any rendering errors do occur.
</Parameter>

<Parameter name="blitwindowid" type="integer" optional default="-1">
If this value is specified, the 3D contents of a different window are blitted (=copied) into this window before calling its own rendering. A common use-case for this are GUI windows that want to show the 3D rendering but not take the performance impact of rendering an expensive scene twice. Instead of rendering the 3D scene, a GUI window would set `draw3d` to `false` and this value to the `id` of the main window, meaning that the contents of that other window are copied and then the 2D UI will be rendered on top of the blitted content. Unless specified otherwise, a window's id is the position of the window within a node, starting at `0`. So the first window of a node will have the id `0`, the second `1`, etc. The value has to be between `-1` and `127`, where `-1` disables the blitting.
</Parameter>

<Parameter name="mirrorx" type="boolean" optional default="false">
If this value is set to `true`, the resulting image of the window will be horizontally mirrored.
</Parameter>

<Parameter name="mirrory" type="boolean" optional default="false">
If this value is set to `true`, the resulting image of the window will be vertically mirrored.
</Parameter>

<Parameter name="monitor" type="integer" optional default="0">
Determines which monitor should be used for the exclusive fullscreen in case `fullscreen` is set to `true`. The list of monitors on the system is zero-based and ranges between `0` and the "number of monitors" - 1, where `0` is the primary monitor as defined by the operating system. If the provided index does not correspond to an existing monitor, the primary monitor is used instead.
</Parameter>

<Parameter name="stereo" type="string" optional default="none">
Determines whether the contents of this window should be rendered stereoscopically and which stereoscopic rendering method should be used. The [Stereoscopy](/docs/reference/stereoscopy) page shows an example image for each of these modes. It has to be one of:

1. `none`: No stereo rendering is performed. This is the same as if this value was not specified. `no_stereo` is an alias for this value.
1. `active`: Using active stereo using quad buffering. This is only a valid option for systems that support quad buffering. `quadbuffer` is an alias for this value.
1. `checkerboard`: Using a checkerboard pattern for stereoscopy in which left and right eyes are rendered on interleaved checkerboard patterns.
1. `checkerboard_inverted`: Using the same pattern as `checkerboard`, but with the left and right eyes inverted.
1. `anaglyph_red_cyan`: Applying color filters to the rendering for the left and right eyes such that red-cyan anaglyph glasses can be used to view the stereo content.
1. `anaglyph_amber_blue`: Applying color filters to the rendering for the left and right eyes such that amber-blue anaglyph glasses can be used to view the stereo content.
1. `anaglyph_wimmer`: Anaglyph method by Peter Wimmer.
1. `vertical_interlaced`: A stereo format in which the left and right eye images are interlaced vertically, meaning that each row of the final image is either left or right, switching each row.
1. `vertical_interlaced_inverted`: The same as `vertical_interlaced`, but with the left and right eye flipped.
1. `dummy`: A dummy stereo mode to test stereoscopic rendering without needing extra equipment. In this stereo mode, the left and the right eye images are rendered on top of each other without any other processing. This option is available to verify that stereo rendering is working for a specific application. `test` is an alias for this value.
1. `side_by_side`: The resolution of the window is split into a left half and a right half, with each eye being rendered into its half. This is a common stereo format for 3D TVs.
1. `side_by_side_inverted`: The same as `side_by_side`, but the left and right images are flipped.
1. `top_bottom`: The same as `side_by_side`, but instead of separating the window horizontally, the window is split vertically, with the left eye being rendered in the top half of the window and the right image being rendered in the bottom half.
1. `top_bottom_inverted`: The same as `top_bottom`, but with the left and right eyes flipped.
</Parameter>

<Parameter name="spout" type="Object" optional>
  Settings for sharing the rendered content of this window to other applications using Spout (only on Windows).

  <Parameter name="enabled" type="boolean">Determines whether the output via Spout is enabled.</Parameter>
  <Parameter name="name" type="string" optional>The name under which Spout will share this content. If this value is not specified, a unique name will be automatically generated.</Parameter>
</Parameter>

<Parameter name="ndi" type="Object" optional>
  Settings for sharing the rendered content of this window over the local network using NDI.

  <Parameter name="enabled" type="boolean">Determines whether the output via NDI is enabled.</Parameter>
  <Parameter name="name" type="string" optional>The name under which NDI will share this content. If this value is not specified, a unique name will be automatically generated.</Parameter>
  <Parameter name="group" type="string" optional>A comma-separated list of NDI groups under which NDI will share the content. See the NDI documentation for more information.</Parameter>
</Parameter>

<Parameter name="scalablemesh" type="string" optional>
If this value is specified, a calibration from Scalable Display Technologies is loaded through Scalable's EasyBlend SDK and used to fill in many of the values of this window instead, such as the window resolution, location, state of full screen etc. This requires SGCT to be built with the `SGCT_SCALABLE_SUPPORT` option. This is unrelated to the Scalable `.ol` [mesh format](/docs/reference/mesh-formats#scalable) that can be used in a viewport's `mesh`.
</Parameter>

<Parameter name="scalablemesh_ortho_quality" type="integer" optional default="2048">
The quality that is used for orthographic projections of a Scalable mesh. This value is only used if `scalablemesh` is specified.
</Parameter>

<Parameter name="scalablemesh_ortho_res" type="integer" optional default="4096">
The resolution that is used for orthographic projections of a Scalable mesh. This value is only used if `scalablemesh` is specified.
</Parameter>

<Parameter name="openxr" type="Object" optional>
  Settings for the support of OpenXR. If the support is enabled, the OpenXR runtime provides all of the information to render the image in accordance with the head-mounted display that OpenXR is configured with.

  <Parameter name="enabled" type="boolean">Controls whether OpenXR is enabled.</Parameter>
</Parameter>
