# Terminology
We use the following terminology to talk about the way SGCT works. The [Glossary](/docs/overview/glossary) contains short definitions of these and other terms that are used throughout this documentation.

There is a single *[Cluster](/docs/reference/configuration/cluster)* that consists of one or more *[Nodes](/docs/reference/configuration/node)*. Each *Node* usually corresponds to a single computer, but multiple nodes can be executed on the same computer, although this is rarely the most optimal solution. All *Nodes* should be connected via low-latency network connections. One of the *Nodes* in the *Cluster* is designated as the *server*, whereas the other *Nodes* are *clients*. Even if a *Cluster* only consists of a single *Node*, it is still considered a server without any clients.

Each *Node* contains one or more *[Windows](/docs/reference/configuration/window)*. Each window uses the operating system's default representation and its resolution, position, and other parameters can be configured. The resolution and position are defined in the native units of the operating system, often logical pixels.

Each *Window* contains one or more *[Viewports](/docs/reference/configuration/viewport)*. A *Viewport* is a part of a window into which some 2D or 3D content can be rendered. The position and the size of each *Viewport* are described in a 0-1 range relative to the window.

If a *Viewport* is set to render 3D content, it must have one of many *[Projection](/docs/reference/configuration/projections)* types that determine how the 3D content is rendered. The most common projection type is the *PlanarProjection* in which a horizontal and vertical field-of-view is defined. Another often used projection type is the *FisheyeProjection* in which multiple render passes are automatically combined to generate a square fisheye or dome master image.
